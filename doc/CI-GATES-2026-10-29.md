# CI budget and gate policy — 2026-10-29

Scope: modernization of rAthena C++17 → C++23.

## Required on each PR

- `modern-toolchain`: GCC Debug/Release, Clang, MSVC, ARM64,
  sanitizers and PCRE2 regression. This is the strongest available
  cross-platform compile/safety gate.
- `modernization-contracts`: standalone behavior tests for real
  C++ utility functions, compiled with GCC and Clang.

## Only when relevant

- `libconfig-vendor`: automatically runs only if a vendored libconfig
  source, its test harness, or its workflow changed. Also callable manually.
- `corpus-regression`: **manual**. Checks NPC manifest references, PyYAML
  syntax and SQL import. Useful before content/database edits, but no
  gameplay proof and not relevant to ordinary C++23 refactors.
- `engine-corpus-runtime`: **manual**. Native login/char/map boot with
  disposable MariaDB, asserts full source corpus load. Useful for loader,
  parser, MariaDB or large dependency changes. Expensive and not a substitute
  for real packet/user flows.

Both manual workflows remain available for high-risk PRs. Never describe
these as having passed a new PR unless someone actually ran them on the
target HEAD. An ordinary `master` squash merge triggers the required gates;
a PR should be merged only after its own exact HEAD has passed.

The prior first-run full engine load was **1,265 maps and 24,169 NPC
instances**. This number represents actual loaded entities, not unique NPC
script files. Static corpus checking was useful once to establish a
baseline but gave diminishing returns on every unrelated PR.
