# C++23 bounded authentication packet encoding

`login-server` previously built the `PACKET_AC_ACK_HASH` reply by casting
the global `packet_buffer` byte array to a flexible-array packet structure,
writing a computed 16-bit length and using `strncpy` to copy the salt.
The caller did not validate the salt length against the actual key array
or the packet buffer before writing.

## Modernized boundary

- `src/common/packet_bytes.hpp` provides an allocation-free encoder using
  **C++20** `std::span` and `std::ranges::copy`, plus **C++23**
  `std::expected` for the two possible bounds failures. It writes the exact
  4-byte little-endian header and copies every salt byte, including NUL.
- `src/login/loginclif.cpp` validates `md5keylen` against `md5key`,
  obtains bounded byte spans via `std::as_bytes` and
  `std::as_writable_bytes`, and sends only the initialized frame.
- `src/common/socket.hpp` adds a bounded `socket_send(fd, span<const
  byte>)` overload; existing fixed- and variable-length packet templates
  remain unchanged for this isolated first migration.
- `tools/packet-bytes-check.cpp` tests exact wire bytes, embedded NUL,
  no overwrite beyond packet length, empty salt, too-short destination,
  maximal 16-bit packet, and oversized salt (which must leave the buffer
  unchanged). Included in both GCC 14 and Clang 19 contract jobs.

The salt is generated by the server; normal packet bytes and length remain
unchanged. This is **not** a wholesale rewrite of the legacy RFIFO/WFIFO and
RBUF/WBUF lvalue macros. Changing those would have a much larger ABI and
protocol compatibility surface and requires call-site auditing first.

## Verification gate

Require the exact PR HEAD to pass C++23 standalone contracts and full
GCC/Clang/MSVC/ARM64/sanitizers matrix. Run the full corpus boot manually
only if investigating a packet or loader integration problem; it does not
perform a real login-client packet handshake.
